huf.

The blueprint: three pieces on your Mac, how a thought moves through them, and where every PRD behavior lives.

Approved

Three pieces, in plain language

In Chrome
The app
TypeScript + React. Screens, the mic, live captions via Chrome’s Web Speech API. Never talks to Claude directly.
On your Mac
The server
Python + FastAPI. Holds your API key in .env, asks Claude to sort and to answer, saves and edits items.
One file
The database
SQLite in server/huf.db. Every memory and reminder lives here, so it survives refresh and restart.

Follow a thought through the system

How Huf avoids making things up

1Only saved itemsClaude gets every saved item with its ID — nothing else to draw from.
2Fixed answer shapefound, answer, used_item_ids — guaranteed by the Pydantic schema.
3Server decides the cardsIDs that don’t exist are dropped. Cards come from SQLite, not from Claude.
4Honest fallbackNot found, or no real IDs left → “I don’t have anything saved about that yet.”

Checked by test_grounding.py, by editing Seattle → Portland and watching the answer change, and by asking about something never saved.

Run it

Two terminals, one Chrome tab local only — no deployment 
# once
cd server && /usr/local/bin/python3.12 -m venv .venv
.venv/bin/pip install -r requirements.txt && cp .env.example .env   # add your key in .env
cd ../web && npm install

# every time
cd server && .venv/bin/uvicorn main:app --reload --port 8000     # terminal 1
cd web && npm run dev                                           # terminal 2

Open http://localhost:5173 in Chrome → DevTools → device toolbar → iPhone 15 Pro. For the recording, delete server/huf.db first so Home starts fresh.

Simplified on purpose · still to verify

Simplifications engineering judgment, nothing faked
  • All items to Claude instead of a vector database — dozens of items fit easily.
  • One table; person as spoken text — matches “keep context as given.”
  • Three tabs as state, no router. Recurrence is a label, not a schedule.
  • Local only; demo in desktop Chrome at iPhone size.
  • No sample data, no simulated answers — every answer comes from real Claude calls on real saved data.
Verify early in the build things I couldn’t confirm from here
  • Reuse existing Python 3.12 (Intel, under Rosetta) for the project venv.
  • messages.parse() with effort: low, and whether the refusal fallback works with parse().
  • Chrome speech recognition on this Mac: permission prompt and silence timing.
